## 0. TL;DR

The user has a personal media library (≈18,300 videos on a NAS, served to Jellyfin) with roughly
14,000 files missing English subtitles. Over four days, a free, zero-dependency Node.js tool was
built, battle-tested against the real library, published to GitHub, and then rebuilt into a
LAN web service with a dashboard (Jellyfin/qBittorrent-style) that is currently running on the
user's desktop. The intended final home is the media server itself; that migration is staged
but not yet performed.

Everything was driven by empirical probing of the real sites and the real library, which produced
a set of hard-won facts (documented in §9) that the code depends on.

## 2. Design decisions (v1)

- **Zero-dependency single Node script** (`subtitles-fetcher.mjs`) — no npm installs at all.
  ZIP parsing, gzip, hashing, HTTP all done with `node:` built-ins.
- **Primary source: SubDL** (see §9) — anonymous, ~300 downloads/day/IP.
- **TV-primary source: Addic7ed** — anonymous, community-synced, release-matched.
- **OpenSubtitles.com official API** — adapter fully implemented but *idle*: needs a free API
  key the user never supplied.
- Downloads always land as `<video-base>.en.srt` next to the video — genuine files are never
  overwritten.
- State in `state.json`: one record per video (`covered | pending | failed | parked | done`,
  provider, release name, timestamp, attempts, lastError, cached metadata, swap history).
- Daily schedule via Windows Task Scheduler (later also cron for Linux).

## 3. User-supplied domain knowledge (pivotal moments)

1. **`sub`/`subs` folders & fake stubs (Aug 27):** many movie folders carry a `Subs/` pack
   (multi-language: `English.srt`, `Arabic.srt`…), and the sidecar `.srt` next to the video is
   often a 1–10 KB junk/HTML stub. → Built content-sniffing detection: sidecars ≥15 KB trusted,
   smaller ones verified for real SRT cues + non-Latin ratio; `Subs/` folders scanned for
   detectable English files. **9 unit tests**, all passing. This alone re-classified ~648 movies
   as already-covered with zero downloads.
2. **SubDL tip (Aug 27):** user suggested subdl.com — anonymous cap ~300/day/IP. Confirmed
   reachable, became the workhorse.
3. **Addic7ed wrapper suggestion (Aug 27):** user found `addic7ed-subtitles-api` on jsdelivr
   (~9 years old, dead) and `same31/addic7ed-api` (2022). Verdict after live testing: site flow
   80% intact but the old parser rotted (Download button moved into `<div class="face-primary">`).
   → Wrote a native adapter instead; Addic7ed became TV-primary.
4. **"Run it on the media server" (Aug 28):** user wants the tool on the M93p, not the desktop.
5. **The web-service vision (Aug 28):** LAN web UI on its own port, `git clone` + one command
   install, boot-time autostart, detached process, folder pickers — then extended with: status /
   reports / live activity, a browsable "what's covered" library with posters, and per-item
   re-search with subtitle swapping. "I don't have any issue with a complete rebuild."

## 6. The v2 rebuild (Aug 28)

Plan first (`docs/plan-web-service.md`, pushed), then execution:

- **Phase 0 — extraction (`4844a7a`):** the 1,432-line monolith split into `lib/` modules with
  zero behavior change. `subtitles-fetcher.mjs` is now a shim; `cli.mjs` holds all 8 commands.
  Tests grew to 14 (9 detection + 5 parser).
- **Phase 1 — service (`cfe219f`):** `service.mjs` (one detached process: web + built-in daily
  scheduler with catch-up + engine; the listening port doubles as the instance lock),
  `lib/webserver.mjs` (token-authed JSON API + SSE live feed + static hosting),
  `web/` dashboard (vanilla JS, dark), `install.mjs` (node version check → config + generated
  token → systemd unit on Linux / `schtasks /SC ONSTART` on Windows → health check → prints
  bookmarkable `http://<lan-ip>:8097/?token=…`).
- **Phases 2–4 (`4af9698`):** dashboard tiles + 14-day downloads chart with provider share,
  folders tab with per-root reachability + counts, queue with retry/park, item modal with
  **history timeline + "Find alternatives" → ranked candidates → one-click swap** (old file kept
  as `.en.srt.1`), settings with token rotation (old token stays valid until restart), and the
  **SubDL soft-block engine rule**: ≥40 consecutive empty-result sd searches after ≥100
  downloads in the UTC day → sd retires for the day and **attempts spent during the streak are
  retroactively forgiven** (re-queued).
- **Deferral rule (`bce739b`):** if no source can serve an item today (e.g. a movie while sd is
  capped and os has no key), it's **skipped penalty-free** — previously such items burned their
  3 attempts daily and parked permanently. After this, the engine zips past un-serviceable
  movies and lives on Addic7ed TV all night; movies resume when quota resets.
- **Priority fetch:** "Fetch Now" on any item or whole show — spliced to the front of the live
  run queue within seconds; if a scan is running, a scoped side-runner handles it (Addic7ed's
  global pacer keeps both polite).
- **Library overhaul (`026620f` + follow-ups):** Movies/TV segmented tabs + live search,
  poster-card grids fed by a server-side art resolver (local Jellyfin art first: episode dir →
  show dir → grandparent, stem-matched across `.jpg/.jpeg/.png/.webp`; poster falls back to
  backdrop/fanart), OMDB fallback (free key in Settings) that **persists fetched posters into
  the library folders** (`poster.jpg`/`backdrop.jpg`, magic-byte validated, never overwrites) so
  Jellyfin benefits too. TV shows render as poster cards opening a **show modal** (poster,
  coverage bar, "Fetch Missing (Priority)", seasons → episode chips → item modal with back
  navigation). Year labels: movies "Inception (2010)", shows "Friends (1994 - 2004)".
- **Async scanner (`2e2dfe2`):** the original scanner was fully synchronous and froze the whole
  service during the ~30-min walk (the exact bug the user hit: "Scan doesn't do anything, logs
  show nothing"). Rewritten to yield every ~150 files — POST /api/scan returns in ~2 ms and
  status/SSE/logs stay responsive mid-scan.

## 7. UI bug chronicle (all fixed, mostly user-discovered)

| Symptom | Root cause | Fix |
|---|---|---|
| Empty modal stuck on screen, Close unresponsive | `#modal { display:flex }` outranks the UA's `[hidden] { display:none }` | `#modal[hidden] { display:none }`, backdrop/Esc close, `Cache-Control: no-cache` on static |
| Movies tab "does nothing" | same bug family: `.cards { display:grid }` vs `hidden` — grid filled invisibly below | global `[hidden] { display:none !important }` |
| Live feed "runs away" while reading | re-render + forced autoscroll per event | append-only rendering; autoscroll only while pinned to bottom; 60-event backfill on load |
| Titles all lowercase / prefixed numbers | v1-era entries had no cached meta → lowercase path-key fallback; padded folder names (`001 …`) | scanner always backfills meta (`p.meta =`, not `??=`); display-layer `prettyTitle`; padded numbering stripped for display while real titles (`1`, `10`, `21`) survive |
| Show named **"$1"** (Drake & Josh) | `replace(/…- Complete…/, "$1")` — regex had no capture group, so `$1` inserted literally | prefix-capturing pattern; plus raw-path fallback so labels self-correct without waiting for a rescan |
| TV years never appeared | scans kept being killed by restarts mid-walk (~30–40 min over WiFi/SMB); no completion → no persisted years | raw-path year fallback in the library endpoint + scan data made authoritative |
| Missing posters (Aaj Robibar `folder.webp`, Adventure Time art in show dir) | extension-locked `.jpg/.png` matching; TV art only checked the episode's own dir; browser had cached the 404 | stem-matching across jpg/jpeg/png/webp; dir traversal up to grandparent; cache-busting + one-shot retry + `no-store` on 404s |
| Console 404s (expired OMDB hotlink, favicon) | blind redirect to cached amazon URL; no favicon route | dead hotlinks purged & served from local persist instead; inline SVG favicon + 204 route |

## 8. Incident: config corruption & state wipe (Aug 28, late)

Writing `config.json` via a bash `node -e` with escaped backslashes **ate the backslashes**
(twice — the second time during a diagnostic, proving the trap rather than fixing it). With
garbage roots, a triggered scan found 0 videos and the scanner's prune step **deleted every
state entry** (nothing "seen"). Recovery: the retired CLI worker's copy at
`C:\Users\Munna\SubtitleFetcher\state.json` had saved continuously until the kill — restored in
full. Standing rule adopted: **generated files with paths go through the Write tool, never
through shell-escaped strings.** Related hardening: `scanRoots` guards transient SMB readdir
failures (`5db9193`).

## 9. Provider & network knowledge base (empirically verified)

**DNS-blocked on this network:** `podnapisi.net`, `api.gestdown.tv`, `yts.mx` (fail even
unsandboxed — ISP/router level). `yifysubtitles.ch` resolves but serves **empty 200s to any
non-browser TLS fingerprint** (curl, Node fetch, and .NET all got 0 bytes) — YTS provider
shipped dormant. `api.opensubtitles.com` reachable and healthy; requires free API key (still not
supplied; `setup`/Settings ready for it).

**SubDL (primary, anonymous):**
- Site search `https://subdl.com/search/<query>`; detail pages `/subtitle/sd<id>/<slug>` — the
  slug must be kept (bare id 404s).
- Page layout: `data-language`/`data-language-name` sections → `data-quality` groups →
  `data-row` items with release `<h4>` and direct `https://dl.subdl.com/subtitle/<id>-<hash>.zip`.
- **ZIPs require `Referer: https://subdl.com`** — otherwise 403 (this is hotlink protection,
  not a quota error; the code once mistook it for a cap).
- **~300 downloads/day/IP.** When exhausted it does **not** error: pages return 200 with results
  silently stripped (the "soft block") — manual one-off probes still succeed, which is why it's
  sneaky.
- ZIPs may contain multi-episode packs; the extractor picks the matching SxxEyy and rejects
  foreign/forced files.

**Addic7ed (TV-primary, anonymous):**
- `srch.php?search=Title+S01E05` → either a results page (`<b>N results found</b>`,
  `serie/Slug/S/E/Name` links) or, for unique matches, a **302 straight to the episode page**
  (must capture `Location` before following — the app initially missed every unique-match show
  because of this).
- Episode page tables: `td.language` → `<b>Completed</b>` or `NN%` → face-button link
  `/original/<showId>/<version>`. Download needs `Referer: <the serie page>`; HI status parsed
  from version headers; release teams extracted for matching.
- No hard cap but **throttles hard when hammered** → global ~3.2 s pacing between hits plus
  cooldown on "too many requests"; transient 503s happen after bursts (retried politely).
- Movies return nothing by design → fall through to SubDL. Practically: **TV runs 24/7,
  movies ride the daily SubDL quota** (~300/day ≈ 6–7 weeks for the full backlog, plus ~940/night
  observed on TV).

**Effective per-video chain:** `a7 → sd → os` (os dormant until a key is added).

## 13. Lessons that shaped the code (for future maintainers)

1. **Probe empirically, never assume** — every provider behavior above (Referer guards, 302
   duality, silent soft-block, TLS fingerprinting) was found by testing, not reading docs, and
   each one has a corresponding code path.
2. **`_` is a regex word character** — `\bS01E01\b` silently fails on `Show_S01E01` names.
   Custom boundaries fixed it (`34f15a0`).
3. **`replace(re, "$1")` with no capture group inserts the literal `"$1"`** — the "$1" show bug.
4. **CSS beats the `hidden` attribute** unless you enforce `[hidden] { display:none !important }`
   — bit twice (modal, tabs).
5. **Shell-escaped backslashes are a trap on Windows** — config files must be written via proper
   file tools; a bad config + a pruning scanner = full state wipe (recoverable only if a good
   copy exists elsewhere — keep one).
6. **Fully synchronous code behind an HTTP endpoint freezes the whole service** — long walks
   must yield to the event loop.
7. **Background children die with their parent session** — launch services detached, and make
   scheduled jobs `StartWhenAvailable` so a powered-off PC just defers work.
8. **Freshness must come from when the data was built, not from file mtimes** — library files
   are years old; the inventory stamp (`state.scannedAt`) is what "20 h old" means.
9. **Browser-cached 404s outlive server fixes** — image misses need `no-store`, cache-busting,
   and a retry path.
10. **Quota exhaustion can masquerade as "no subtitles exist"** — detect streaks, retire the
    source, and forgive the attempts it wasted.
